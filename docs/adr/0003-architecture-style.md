# 3. Модульный монолит

- **Статус**:
- **Дата**: 2026-11-07
- **Участники**: вся команда

## Контекст
Нужно решить, как система организована в целом: одно приложение или несколько служб.

## Движущие факторы
- `C-04`: команда из 2 человек, один семестр.
- `NFR-04`: сохранность данных при перезапуске — проще обеспечить одной базой.
- Предложение о структуре кода из ЛР 2Б: контексты — модули внутри `domain/`.

## Рассмотренные варианты
| Вариант | За | Против |
|---|---|---|
| **Модульный монолит** | Одно развертывание; согласованность данных; предметная логика проверяется без внешних средств. | Границы поддерживаются договоренностью. |
| Микросервисы | Независимые выпуски. | Три конвейера, три набора наблюдаемости, распределенные отказы. При `C-04` неисполнимо. |

## Решение
**Модульный монолит.** Одно приложение, одна база данных, явные границы между предметной областью и инфраструктурой. Определяющий довод — `C-04`: независимость служб при одной команде не дает ничего.

## Последствия

- **Положительные.** Одно развертывание, одна база. Предметная логика проверяется без внешних средств.
- **Отрицательные.** Все части выпускаются вместе. Границы обеспечены договоренностью.
- **Что пересмотрит решение.** Появление второй команды, работающей над системой независимо.
