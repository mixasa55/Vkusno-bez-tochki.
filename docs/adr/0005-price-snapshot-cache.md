# 5. Кэш снимка цен вместо синхронного запроса к магазинам

- **Статус**: Принято
- **Дата**: 2026-11-07
- **Участники**: вся команда

## Контекст
Конфликт требований К-1 (`docs/requirements.md`, раздел 12). `FR-03` требует показать цену недостающих ингредиентов в ближайшем магазине. `NFR-01` требует, чтобы 95 % запросов поиска укладывались в 500 мс. Источник цен — внешние открытые страницы (`C-03` запрещает платные API), время ответа которых нами не управляется.

## Движущие факторы
- `NFR-01`: 500 мс на 95 % запросов при 10 rps.
- `FR-03`: цена рядом с недостающим ингредиентом; `AC-03.2` допускает показ без цен.
- `C-03`: только открытые данные, платного API с гарантированной задержкой нет.
- `NFR-03`: данные должны переживать перезапуск сервиса.
- События ЛР 2Б: «Снимок цен устарел», «Парсер обновил снимок цен» — цены меняются раз в сутки, а не на каждый запрос.

## Рассмотренные варианты
| Вариант | За | Против |
|---|---|---|
| **Синхронный запрос к магазину в ответе поиска** | Цены самые свежие. | Задержка внешнeгo источника попадает в `NFR-01`; при недоступности магазина падает весь поиск. |
| **Кэш-обёртка над синхронным запросом (cache-aside)** | Актуальность по требованию. | Первый запрос всё равно медленный; холодный кэш под нагрузкой даёт тот же провал `NFR-01`. |
| **Снимок цен (`PriceSnapshot`), который пишет фоновый парсер** | Чтение из своей БД — единицы миллисекунд; поиск не зависит от доступности магазина; снимок переживает перезапуск (`NFR-03`). | Цены отстают на время до следующего прогона; нужен отдельный запускаемый процесс. |

## Решение
**Снимок цен, который обновляет фоновый парсер.** Поиск читает последний валидный `PriceSnapshot` из PostgreSQL. Парсер запускается по расписанию раз в сутки, снимок имеет TTL в один час. Если валидного снимка нет — показываем недостающие ингредиенты без цен и плашку «Цены временно недоступны» (`AC-03.2`).

Определяющий довод: `NFR-01` невыполним, если время ответа внешнего источника входит в время ответа поиска.

## Последствия

- **Положительные.** `NFR-01` выполняется независимо от состояния магазинов. Отказ источника цен деградирует до `AC-03.2`, а не до ошибки поиска. Снимок лежит в БД — `NFR-03` выполняется бесплатно.
- **Отрицательные.** Цена может устареть до одних суток; пользователь видит цену с пометкой момента сбора. Появляется второй исполняемый вход (парсер) — его надо развёртывать, мониторить и тестировать отдельно.
- **Что пересмотрит решение.** Появление источника цен с гарантированной задержкой ответа (например, официальный бесплатный API магазина) — тогда возвратимся к cache-aside.
