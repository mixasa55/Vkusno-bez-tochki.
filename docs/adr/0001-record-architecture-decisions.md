# 1. Мы ведем записи об архитектурных решениях

- **Статус**: Принято
- **Дата**: 2026-11-07
- **Участники**: вся команда

## Контекст
Решения о структуре системы принимаются в разговоре и не фиксируются. Через месяц причина решения не воспроизводится.

## Движущие факторы
- Защита проекта требует обоснования принятых решений.
- Участники работают в разное время, решения нужно передавать письменно.

## Рассмотренные варианты
| Вариант | За | Против |
|---|---|---|
| **Записи в репозитории по формату MADR** | Рядом с кодом, проходят ревью, история в Git. | Нужна дисциплина. |
| Раздел в общем документе требований | Одно место. | Решения тонут среди требований. |
| Не фиксировать | Ничего не нужно делать. | Текущее положение, которое привело к проблеме. |

## Решение
Записи в репозитории, в каталоге `docs/adr/`, по формату **MADR**. Одно решение — один файл. Записи не правят и не удаляют, а заменяют новыми.

## Последствия

- **Положительные.** Причина решения доступна через месяцы.
- **Отрицательные.** Запись требует времени (от 20 минут).
- **Что пересмотрит решение.** Появление единого требования к оформлению документации.
