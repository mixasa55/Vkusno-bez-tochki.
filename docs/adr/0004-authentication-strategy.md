# 4. Стратегия аутентификации и авторизации

- **Статус**: Принято
- **Дата**: 2026-11-07
- **Участники**: вся команда

## Контекст
Требуется решить, будет ли система требовать регистрацию и вход. `C-04` (команда из 2 человек) и `C-05` (только русский язык) сужают выбор. `NFR-01` (ответ ≤ 500 мс) накладывает ограничение на сложность проверки токена.

## Движущие факторы
- `C-04`: авторизация требует отдельного модуля, базы пользователей, обработки паролей и токенов.
- `FR-*` в MVP не привязаны к конкретному человеку — все запросы публичные.
- `NFR-01`: проверка JWT добавляет 10–50 мс и лишний запрос к БД.
- `NFR-02`: журналирование требует `request_id`, но не привязки к пользователю.
- `AC-03.4`: геолокация не обязательна — значит, и личность пользователя не нужна для выбора магазинов по умолчанию.

## Рассмотренные варианты
| Вариант | За | Против |
|---|---|---|
| **Без аутентификации в MVP** | Нет дополнительного модуля, нет базы пользователей, все FR-работают. | Невозможно персонализировать; нет истории поиска. |
| JWT-токен с регистрацией | Можно персонализировать, хранить историю поиска. | Требуется `Users`, `Passwords`, `RefreshToken`; усложняет БД и API; нарушает `C-04`. |
| OAuth через соцсеть | Удобно для пользователя. | Ещё больше зависимостей, внешние провайдеры, `C-03` запрещает платные API (и необязательно бесплатные). |

## Решение
**Без аутентификации в MVP.** Все запросы к API публичные. Пользователь не входит в систему. Геолокация опциональна, поиск — без личного кабинета. Решение фиксируем как ADR, чтобы в ЛР 4Б осознанно вернуться и решить, нужна ли авторизация.

## Последствия

- **Положительные.** Нет модуля пользователей, нет обработки паролей, нет токенов. Время ответа `POST /api/v1/recipes/search` остаётся ≤ 500 мс без учёта проверки авторизации.
- **Отрицательные.** Нет истории поиска, нет избранного, нет персонализации. Любой пользователь видит те же рецепты.
- **Что пересмотрит решение.** Появление требования «хранить историю поиска» или «избранное» — это потребует `Users` и JWT/OAuth, тогда примем ADR с альтернативой.
