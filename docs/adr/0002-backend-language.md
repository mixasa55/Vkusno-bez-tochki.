# 2. Язык и каркас серверной части

- **Статус**:
- **Дата**: 2026-11-07
- **Участники**: вся команда

## Контекст
Нужен язык серверной части на весь семестр. Язык задан кафедрой (`C-01`); запись фиксирует, подходит ли он проекту.

## Движущие факторы
- `C-04`: команда из 2 человек, один семестр — объем, который реально освоить, важнее скорости исполнения.
- `NFR-05`: прогон тестов не дольше 60 секунд — требует языка с быстрым запуском.
- `FR-*`: контракт API понадобится в ЛР 4Б — предпочтителен каркас, формирующий описание OpenAPI сам.

## Рассмотренные варианты
| Вариант | За | Против |
|---|---|---|
| **Python + FastAPI** | Проверка данных и описание API из коробки; низкий порог входа. | Скорость исполнения ниже; ошибки типов ловятся отдельным инструментом. |
| Go + net/http | Высокая скорость; статическая типизация. | Многословнее; описание API и проверка данных пишутся руками. |
| C# + ASP.NET Core | Сильная платформа; развитая среда разработки. | Тяжелее окружение. |

## Решение
**Python 3.14 + FastAPI.** Определяющий довод — объем, который команда успевает освоить за семестр: проверка данных и описание API даются каркасом.

## Последствия

- **Положительные.** Модели `pydantic` переиспользуются как проверка данных и как описание OpenAPI.
- **Отрицательные.** Проверка типов — отдельный этап конвейера (`mypy`).
- **Что пересмотрит решение.** Требование обрабатывать десятки тысяч запросов в секунду.
