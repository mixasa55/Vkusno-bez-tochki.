# Агрегаты (ЛР 2Б)

## Рецепт (Recipe) — основной агрегат

**Корень**: `Recipe`
**Контекст**: Рецепты

### Состав
| Элемент | Вид | Почему так |
|---|---|---|
| `Recipe` | Сущность, корень | Имеет тождество (ID), меняется со временем. |
| `Ingredient` | Сущность | Имеет ID, хранится отдельно (справочник). |
| `Nutrition` | Значение | КБЖУ на 100г. Не имеет ID, определяется числами. |

### Инварианты
| № | Инвариант | Почему инвариант |
|---|---|---|
| И-1 | КБЖУ не может быть отрицательным | Проверяется по данным агрегата. |
| И-2 | Время приготовления > 0 | По данным агрегата. |

### Что инвариантом не является
| Правило | Почему не инвариант | Где проверяется |
|---|---|---|
| «Рецепт должен содержать только имеющиеся ингредиенты» | Требует данных от пользователя (другой агрегат). | Правило сценария (Поиск). |

### События
| Событие | Когда | Что несет |
|---|---|---|
| `RecipeCreated` | Создан рецепт | ID, название, состав. |
| `RecipeUpdated` | Изменен рецепт | ID, новые данные. |

### Границы
Ссылка на ингредиенты — по ID. Сам справочник ингредиентов — отдельная сущность (может быть вынесена в другой контекст, но для MVP оставляем в Рецептах).

## Магазин (Store) — поддерживающий агрегат

**Корень**: `Store`
**Контекст**: Цены и Магазины

### Состав
| Элемент | Вид | Почему так |
|---|---|---|
| `Store` | Сущность | Имеет ID, адрес. |
| `Price` | Значение | Цена на товар. |

### Инварианты
| № | Инвариант |
|---|---|
| И-3 | Цена не может быть отрицательной. |
| И-4 | Координаты магазина валидны (широта/долгота). |

### События
| Событие | Когда | Что несет |
|---|---|---|
| `PriceUpdated` | Обновлены цены (парсер) | ID магазина, ID ингредиента, новая цена. |
