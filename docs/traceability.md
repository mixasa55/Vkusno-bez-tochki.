## Обратная проверка: шаг пути пользователя → требование

| Шаг пути (из требований, раздел 5) | Из какого требования следует |
|---|---|
| «Что приготовить?» | Вне системы — намерение персоны |
| Ввёл ингредиенты | `FR-01` |
| Увидел список рецептов | `FR-01`, `FR-04` |
| Открыл рецепт | `FR-02` |
| Посмотрел КБЖУ | `FR-02` |
| Увидел, чего не хватает и почём | `FR-03` |
| Перешёл к приготовлению | `FR-05` |

Все семь шагов пути покрыты требованием; «что приготовить» — намерение, а не поведение системы.

## Обратная проверка: решение без требования

| Элемент архитектуры | Какое требование закрывает |
|---|---|
| `PRICE_SNAPSHOT`, фоновый парсер | `FR-03` + `NFR-01` (конфликт К-1, [ADR-0005](./adr/0005-price-snapshot-cache.md)) |
| Отсутствие `users` и токенов | Решение не делать ([ADR-0004](./adr/0004-authentication-strategy.md)); требует `C-04` |
| `COOKING_STEP` отдельной сущностью | `FR-05` (И-5) |
| Денормализация `calories_per_portion` | `FR-04` + `NFR-01` |

Золотых украшений (конструкций без требования) в модели данных и контейнерах нет.
