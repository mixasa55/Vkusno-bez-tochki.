## Соглашение о нотации C4

Одинаковое во всех диаграммах `c4/`, чтобы цвет читался без легенды:

| Класс Mermaid | Значение | Кто на диаграмме |
|---|---|---|
| `actor` | Человек или роль | Пользователь, Спортсмен, Оператор сервиса |
| `sys` | Программная система или контейнер с кодом | Сервис, API-сервис, Веб-интерфейс, Парсер |
| `store` | Хранилище | База данных PostgreSQL |
| `ext` | Внешняя система, вне нашего контроля | Страницы магазинов, справочник КБЖУ, OSM |

Правила, которые соблюдаем при каждой правке:

1. Подпись связи содержит **что передаём** и **протокол**, а не только стрелку.
2. Внешние системы не знают о нашей внутренней структуре и не появляются на диаграмме контейнеров как часть границы.
3. Последовательность рисует только участников из `c4/container.mmd`; если участника нет там — его нет и в последовательности.
4. Модель данных не вводит колонку, которой нет в агрегатах `../domain/aggregates.md`, и наоборот.
5. Любое решение на диаграмме имеет ссылку на `FR-*`, `NFR-*`, `C-*`, инвариант (И-*) или ADR.

## Как обновлять

1. Изменение видно на диаграмме — правим `.mmd` в том же запросе на слияние, что и код.
2. Изменение принято как решение — сначала запись в `../adr/`, потом диаграмма.
3. После правки прогоняем сверки ниже и обновляем дату в коммите.
4. Диаграмма, не подтверждённая кодом, помечается в подписи «проект».

## Чего здесь нет и почему

| Отсутствует | Причина |
|---|---|
| Диаграмма компонентов | Модульный монолит из двух пакетов ([ADR-0003](../adr/0003-architecture-style.md)); состав виден в структуре каталогов |
| Диаграмма развертывания | Один хост, три контейнера Docker; отличий от `c4/container.mmd` пока нет |
| Диаграмма «код» (классы) | Генерируется из типов Python по требованию, в актуальном состоянии не поддерживается |
| Схема сети и балансировщик | Учебный контур, отказоустойчивость не требуется по `NFR-03` |
| Диаграмма аутентификации | Авторизации нет ([ADR-0004](../adr/0004-authentication-strategy.md)) |

## Результат пяти сверок

Проверено 2026-11-07 при подготовке ЛР 2Г.

| № | Что сверяли | Результат | Что исправили |
|---|---|---|---|
| 1 | Контекст ↔ контейнеры | Расхождение | В `context.mmd` цены шли как «REST API магазинов»; по факту это парсинг страниц — привели обе диаграммы к «открытые страницы магазинов» |
| 2 | Контейнеры ↔ модель данных | Расхождение | На контейнерах не было хранилища снимков цен; добавлены `PRICE_SNAPSHOT` и `STORE_PRODUCT` в `data/model.mmd` |
| 3 | Последовательность ↔ контейнеры | Расхождение | Диаграмма рисовала `actor` и три участника без веб-интерфейса; привели участников к списку из `container.mmd` |
| 4 | Модель данных ↔ агрегаты | Расхождение | КБЖУ хранилось одной колонкой `calories` на ингредиенте; развели на `*_per_100g` (значение `Nutrition`) и вычисляемое КБЖУ порции, добавили `COOKING_STEP` по агрегату «Рецепт» |
| 5 | Диаграммы ↔ требования | Расхождение | Не было покрытия `FR-04` и отказных веток `AC-03.2`/`AC-04.2`; добавлены фильтр в запрос и три ветви отказа |
