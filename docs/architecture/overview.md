# Обзор архитектуры

Документ отвечает на вопрос «почему система устроена именно так». Детали организации — в `docs/adr/`, схемы — в `docs/architecture/`, чтение начинается с [README](./README.md).

## 1. Границы системы

**Внутри системы** — то, что команда разрабатывает и развертывает сама:

| Часть | Что делает | Контейнер |
|---|---|---|
| Модуль `recipes` | Поиск по ингредиентам, расчёт КБЖУ порции, шаги приготовления | API-сервис |
| Модуль `pricing` | Чтение снимка цен, стоимость докупки | API-сервис |
| Парсер | Сбор цен и координат, запись нового снимка | Парсер цен |
| Хранилище | Рецепты, состав, шаги, магазины, снимки цен | PostgreSQL |
| Веб-интерфейс | Формы ввода и карточка рецепта | Веб-интерфейс |

**Снаружи** — то, чем команда не управляет:

| Внешняя система | Что берём | Что делаем при её отказе |
|---|---|---|
| Открытые страницы магазинов | Цены продуктов | Показываем состав без цен и плашку (`AC-03.2`) |
| Открытый справочник КБЖУ | КБЖУ на 100 г | Показываем «КБЖУ временно недоступно» (`AC-02.2`) |
| Открытые карты (OSM) | Координаты магазина | Используем координаты из сохранённого справочника магазинов |

Граница проведена по правилу: система не отвечает за чужую доступность, но обязана деградировать предсказуемо — каждое такое поведение закреплено критерием приемки.

## 4. Требования к качеству → тактика → место

| Требование | Тактика | Где реализуется | Как проверить |
|---|---|---|---|
| `NFR-01` (95 % ≤ 500 мс) | Убрать внешние вызовы из пути запроса; чтение из своей БД | `ADR-0005`; индекс по `recipe_ingredient.ingredient_id`; `calories_per_portion` как денормализация для фильтра | [data/model.mmd](./data/model.mmd) |
| `NFR-02` (JSON-журнал) | Единый формат записи на границе запроса | Промежуточный обработчик FastAPI: `timestamp`, `level`, `event`, `request_id` | [container.mmd](./c4/container.mmd) — API-сервис |
| `NFR-03` (сохранность при перезапуске) | Состояние только в PostgreSQL, процесс без локального кэша | `PRICE_SNAPSHOT` в БД, а не в памяти процесса | [data/model.mmd](./data/model.mmd) |
| `NFR-04` (тесты ≤ 60 с, покрытие ≥ 70 %) | Границы модулей позволяют тестировать домен без БД | Пакеты `recipes`/`pricing` без импортов инфраструктуры | [ADR-0003](../adr/0003-architecture-style.md) |
| `NFR-05` (4 из 5 находят с первой попытки) | Одна форма ввода, ошибка — у поля, пустой результат с подсказкой | Ветви отказа последовательности и `AC-01.2`, `AC-04.2` | [sequence/search-recipes.mmd](./sequence/search-recipes.mmd) |

## 5. Защищённость (STRIDE)

Авторизации нет ([ADR-0004](../adr/0004-authentication-strategy.md)), поэтому часть угроз снимается отсутствием субъекта, а не механизмом.

| Угроза | Применимо | Мера | Остаточный риск |
|---|---|---|---|
| **S** — Маскировка | Нет учётных записей | Не применимо: персональные данные не собираются, геолокация опциональна и не сохраняется | Низкий |
| **T** — Подмена данных | Да: парсер пишет цены из внешнего источника | Проверка схемы перед записью; снимок создаётся новым, а не правится; аномальная цена (> 3× медианы) отбрасывается | Средний: источник может соврать намеренно |
| **R** — Отказ от авторства | Да: парсер может «не заметить» прогон | Каждый снимок хранит `collected_at` и `source_status`; прогон пишется в журнал с `request_id` | Низкий |
| **I** — Раскрытие информации | Да: запрос с ингредиентами — про питание человека | Ингредиенты не пишутся в журнал и не хранятся; журнал содержит только `request_id` и длительность | Низкий |
| **D** — Отказ в обслуживании | Да: 10 rps по `NFR-01` | Ограничение размера ввода (не более 3 ингредиентов, ≤ 40 символов), пагинация выдачи, запрос к БД с лимитом | Средний: парсер может заблокировать запись снимка |
| **E** — Повышение привилегий | Нет ролей | Не применимо до появления авторизации; при её появлении нужен отдельный ADR | Низкий |

Данные о питании относятся к чувствительным, поэтому решение не хранить ввод пользователя принято как мера приватности, а не как экономия.

## 6. Что осознанно не сделано

| Не сделано | Почему | Когда пересматриваем |
|---|---|---|
| Аутентификация и личный кабинет | Нет требования, привязанного к человеку | Появится «избранное» или история поиска |
| Очередь сообщений между парсером и API | Монолит, один снимок в сутки (`C-04`) | Второй источник цен или обновление чаще одного раза в час |
| Кэш в памяти (Redis) | Чтение из PostgreSQL укладывается в `NFR-01`, лишнего процесса не хотим | Замер покажет > 500 мс на 10 rps |
| Микросервисы | `C-04` | Вторая команда в системе |
| Мобильное приложение | Веб-интерфейс закрывает сценарий | Требование офлайн-режима |
| Миграция схемы «на живую», сине-зелёный выпуск | Учебный контур, допустим простой в 30 с (`NFR-03`) | Реальные пользователи |
| Тесты на доступность и нагрузочное тестирование безопасности | Вне объёма проверки `NFR-04` | ЛР 5Б |
