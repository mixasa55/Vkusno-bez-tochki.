# Дизайн API (REST)

Все запросы к API идут с префиксом `/api/v1`.

## 1. Поиск рецептов
* **POST `/api/v1/recipes/search`**
  * *Описание:* Найти рецепты по имеющимся ингредиентам и параметрам.
  * *Тело запроса (JSON):*
        {
          "ingredients": ["курица", "рис", "помидор"],
          "filters": {
            "max_time_min": 30,
            "max_calories": 500,
            "budget_limit": 300
          },
          "location": {
            "lat": 55.75,
            "lon": 37.61
          }
        }
  * *Ответ (200 OK):* Список рецептов с краткой инфой, КБЖУ и стоимостью недостающих продуктов.

## 2. Детали рецепта
* **GET `/api/v1/recipes/{recipe_id}`**
  * *Описание:* Получить полную инструкцию, список ингредиентов, КБЖУ.
  * *Ответ:* Объект рецепта с массивом шагов `steps`.

## 3. Цены и магазины
* **GET `/api/v1/prices/missing`**
  * *Параметры:* `recipe_id`, `lat`, `lon`.
  * *Описание:* Возвращает список недостающих ингредиентов и цены на них в 3-х ближайших магазинах.

## 4. КБЖУ (Справочник)
* **GET `/api/v1/ingredients/autocomplete?q=кур`**
  * *Описание:* Автодополнение для поля ввода (возвращает список ингредиентов, начинающихся на "кур").

## 5. Обработка ошибок (RFC 7807)
Все ошибки возвращаются в едином формате:
{
  "type": "https://api.example.com/errors/validation",
  "title": "Ошибка валидации",
  "status": 400,
  "detail": "Ингредиент 'абракадабра' не найден в базе"
}
